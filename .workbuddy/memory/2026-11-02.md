# 2026-11-02 工作日志

## 修复「和平公园」高德取不到 AOI（名称相关性过滤缺陷）

- **现象**：`get-aoi run` 搜「和平公园」（上海），日志 `候选 25 → 过滤 12 → 名称相关 1`，唯一幸存者是「和平公园老面馒头店(杨浦分店)」，馒头店无边界 → `No Geometry`。而直接访问隐藏接口 `getPoiInfo?id=B001510563` 有 `spec.mining_shape.shape`。
- **根因（非反爬/Cookie）**：`core/filter.py` 的 `relevant_candidates` 只接受「精确同名」或「query 开头 + 分支后缀」两种。高德官方名「**上海**和平公园」带城市前缀、不以 query 开头 → 被误杀；而「和平公园**老面馒头店(杨浦分店)**」以 query 开头且后缀含「分店」→ 被误判为公园的分支留下。
- **修复（增量）**：
  1. `relevant_candidates` 增加 `normalized.endswith(query)` 分支——前缀是城市/行政区（上海和平公园、上海市同济大学）时视为同一目标。
  2. `_is_branch_variant` 收紧分支词判断：`校区/分院/分店` 等须紧跟名称（`normalized_suffix.find(word) <= 4`），避免「老面馒头店(杨浦分店)」里的「分店」被误认。
- **验证**：`和平公园` 现在选中 `B001510563(上海和平公园)`，抠到面 0.15755 km²；新增 2 个 filter 测试，全量 80 测试全绿。

## 附带确认的高德反爬事实

- 高德隐藏接口 `getPoiInfo` 无 Cookie 时稳定返回 `FAIL_SYS_USER_VALIDATE / RGV587_ERROR`（`_check_antibot` 能识别，会抛 `AntiBotError`）。
- 用户 `configs/keys.txt` 里的 `amap_cookie`（1604 字符）+ `amap_user_agent` 是有效的，带上即可正常返回 shape（格式 `经度,纬度;经度,纬度;...`）。

## 「黄兴公园」商圈噪音：根因是 page_size 差异

- 百度 `place/v2/search` 检索「黄兴公园」时，商圈（`行政地标;商圈`，uid `6f7492cd…`）排在结果**第 12 名**。用户手动 URL 未带 `page_size`（默认 10 条）看不到；工具用 `page_size=20` 抓到了它，`want=all` + `keep_types:""` 时被保留，单独抠出 5.5km² 的商圈面。
- 商圈是**独立 POI**（自己的 uid/边界），不是从公园 uid 的 `qt=ext` 来的；`qt=ext` 按 uid 单查。
- 解法已生效：`keep_types: "旅游景点"` 在分类闸拦住 `行政地标`。备选：把「行政地标」加入默认排除（用户尚未拍板，方案待定）。

## 额度机制（已向用户讲清）

- 只有 search（名称→id，官方接口带 key/ak）消耗额度；fetch_boundary（getPoiInfo / qt=ext，隐藏接口无 key/ak）**不消耗额度**。
- 翻页会多耗：百度 page_size=20、高德 offset=25，重名地名翻页每页 1 次额度。额度消耗 = search 请求总次数（含翻页）≈ 名称数 × 平均翻页数。

## 修复断点续跑覆盖历史成果（C 方案：BoundaryCache 回填）

- **现象**：`get-aoi run -c ... --resume runs/xxx` 续跑后，之前已完成名字的 AOI 面全部丢失（导出只剩本次新抓的）。用户确认「续跑覆盖了之前的数据」。
- **根因（三件事叠加）**：① `state.json` 只存 `poi_id/name/area_km2` 摘要，**不存几何**；② 续跑时 `all_records=[]` 从空起步，已完成名字被 `is_done` 跳过、不会重新进结果集；③ 导出是覆盖写（geojson `write_text` / gpkg `to_file`）到同一 `outputs/aoi.*`。
- **选型**：三方案对比（A 断点存几何 / B 合并上次输出 / C 用现成 BoundaryCache 回填）后选 **C**——`core/cache.py` 的 `BoundaryCache` 已按 `provider|poi_id` 存完整几何且有 `_record_from_json` 反序列化，改动最小、几何不冗余、性能最好。
- **实现**：`cli.py` 新增 `_restore_completed(state, provider, cache, all_records, summary)`，续跑时遍历 `state.data`，无面结论（No Candidate/No Geometry）直接恢复 summary；有面项用 poi_id 从 cache 回填；cache 缺失或 `cache=None`（未启用）时**清除完成标记 + warning**，交给流程重抓（边界请求仍命中缓存、仅多耗检索额度）。
- **文档**：README 在特性、运行方式、`--resume` 参数、FAQ、性能调优「缓存」五处写明续跑前提 `cache.enabled: true`，并提醒清空缓存目录会破坏续跑回填。
- **验证**：新增 `tests/test_resume.py` 6 个单测（命中回填 / No Candidate / cache miss 重开 / 无缓存重开 / 部分命中整体重开 / provider 隔离）；全量 86 测试全绿。
